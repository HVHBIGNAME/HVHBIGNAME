# HVH / BIGNAME — selected work

Шесть кликабельных SVG-сцен: обложка, четыре избранных проекта и публичная
активность GitHub. Название, описание, стек и переход находятся внутри карточки.
Дополнительные ссылки и автоматически обновляемая таблица свёрнуты в журнал.

## Визуальное направление

Тёмный оливковый графит, тёплый белый текст, приглушённые природные акценты,
крупная типографика и один объёмный объект на проект. Светлая тема — молочная,
с контрастным тёмным текстом. Иллюстрации сохраняют собственные материалы.
Фон статичен; мягкий свет сосредоточен вокруг объекта. Нет полноэкранных
вспышек, шумового фильтра поверх текста или непрерывно скачущих заголовков.

Принцип motion-референса [Garagoro](https://github.com/Garagoro): большой
предмет входит в сцену, раскрывается текст, затем остаётся спокойное движение.
Иллюстрации для HVH нарисованы отдельно; сторонние SVG и модели не используются.

| Сцена | Объект и появление |
| :-- | :-- |
| `#hero` | Три металлические буквы HVH сходятся из разных направлений |
| `#bcore` | Изометрический ландшафт собирается из блоков, ядро опускается сверху |
| `#minecraft-panel` | Слои emberdeck складываются в панель, появляется консоль |
| `#softdownloader` | Иконки сходятся над каталогом, заполняется полоса установки |
| `#opencode-pocket` | Компьютер и телефон сходятся в композицию, появляется отметка связи |
| `#signal` | Реальные дневные столбцы поднимаются от общей базовой линии |

UI внутри иллюстраций — схематическая демонстрация продукта, не текущая
телеметрия. Данные в `#signal` получаются из GitHub API.

## Адаптация

Каждый вид имеет размер **1200 × 520**. У корневого атласа нет `height`:
пропорции `<img>` задаёт выбранный `<view>`. README использует `?v=hvh6`.
Тему выбирает `<picture>`, компоновку — медиазапрос внутри SVG до 600 px.

На компьютере текст слева, объект справа. На телефоне длинные названия
переносятся на две строки, объект уменьшается в правом верхнем углу,
описание занимает отдельную полосу под ним. Иллюстрации остаются непрозрачными.

## Одна временная шкала

Шесть `<img>` ссылаются на один файл темы с разными фрагментами. Движение
задано напрямую через SVG `<animate>` и `<animateTransform>`. CSS отвечает
только за типографику, адаптацию и reduced motion.

Начало элементов зависит от роли, а не от индекса карточки:

| Время | Событие |
| :-- | :-- |
| 0.15s | Появление подписи сцены |
| 0.20s | Начало диагонального раскрытия текстового блока |
| 0.30s | Подъём названия |
| 0.35s | Одновременная сборка объектов во всех карточках |
| 0.60s | Появление описания |
| 0.80s | Нижняя подпись и ссылка |
| ≤ 2.25s | Сборка закончена |
| 2.60s | Начало общего спокойного 12-секундного цикла |

Влёт использует замедление `.16 1 .3 1`; раскрытие и движение в покое —
`.45 0 .25 1`. Для объектов используются вложенные группы: расположение →
движение в покое → сборка деталей. Анимация никогда не заменяет адаптивную
трансформацию `.art-anchor`.

После вступления предметы слегка поднимаются и опускаются, на HVH проходит
редкий блик, по связи компьютера и телефона движется пунктир. Период и начало
всех повторений задаются `CYCLE_SECONDS` и `INTRO_END` в `motion.py`.
Интро не повторяется при прокрутке; повторный старт зависит от новой загрузки
или пересоздания SVG-ресурса браузером.

## Границы и статичная версия

У каждой `scene-*` есть собственный локальный clipPath 1198 × 518. Внешняя
группа задаёт только вертикальное положение в атласе. Даже разлетающиеся
части объектов не должны попадать в соседнюю карточку.

`svg_timeline.py` создаёт статичные копии сцен по явно заданным `data-rest-*`:
удаляет SMIL, сбрасывает входные смещения, снимает reveal-клип и удаляет
временные блики. При `prefers-reduced-motion: reduce` показывается именно
эта законченная неподвижная композиция. CSS `animation:none` не применяется
как замена остановке SVG-анимации.

## Исходники и сборка

- `design.py` — композиция, текст, палитры, график и атлас.
- `illustrations.py` — предметы проектов и внутренние детали.
- `brand.py` — общие контуры монограммы, металл, статичные экспортируемые знаки.
- `motion.py` — временная шкала, функции анимации и материалы.
- `svg_timeline.py` — доступная статичная версия.
- `generate_profile.py` — API GitHub и обновление данных.

```sh
python scripts/design.py
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/verify_visuals.py --output /path/to/review
```

Генерация работает на стандартной библиотеке Python. Офлайн-сборка использует
`assets/activity.json`; SVG редактируются через исходники. Браузерной проверке
нужны Playwright, Chromium и Pillow.

Визуальные проверки:

- обе темы, desktop и mobile; границы текстов и пропорции реальных `<img>`;
- полная сцена против изолированной в пяти моментах интро/цикла;
- законченная неподвижная версия reduced motion;
- кадры вступления, матрицы и растр через один и пять циклов;
- общий SVG-маркер времени в шести изображениях и поздно добавленном седьмом,
  до и после прокрутки. Маркеры создаются тестовым HTTP-сервером и не публикуются.

Перед общим снимком все изображения выводятся в viewport и ожидается новый
paint: full-page screenshot может содержать старый offscreen-растр.
Допуск изоляции — 3/255 для сглаживания. Проверка периода сопоставляет матрицы
с точностью .001 SVG-unit, среднюю разницу растра ≤ .01/255 и долю изменённых
более чем на 3/255 пикселей ≤ .0001. Это учитывает float32-округление SVG-часов
на отдельных сглаженных границах. Между IMG-маркерами допустимо до 2px.
Отчёты PNG/JSON и GIF-превью сохраняются в заданный каталог.

## Публичные данные

Actions запускается на 17-й минуте каждого часа, при изменении README,
скриптов или workflow, а также вручную. Возможны задержки GitHub.
Обновляются оба атласа, `activity.json` и таблица `PROJECTS:START / END`.

Даты — UTC. Contributions включают публичные коммиты, issues, pull requests
и reviews. Нулевые дни остаются нулевыми. Все запросы и отрисовка завершаются
до записи; ошибка API сохраняет предыдущий результат. При неизменных данных
новый коммит не создаётся.
