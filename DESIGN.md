# HVH / BIGNAME

Шесть SVG-карточек: обложка, четыре проекта и публичная активность GitHub.
Описание, стек, статус и кнопка находятся внутри картинки. Карточка проекта
целиком обёрнута ссылкой; дополнительные ссылки находятся в свёрнутом журнале.

## Композиция

Графитовый фон, серебристый знак HVH, локальная подсветка иллюстраций.
У каждого проекта свой акцент: зелёный BCore, медный emberdeck, голубой
SoftDownloader, сиреневый OpenCode Pocket. В светлой теме фон холодный серо-белый.
Зерно статичное, с прозрачностью .035 / .025; цветная аура имеет максимум .14.

Монограмма состоит из двух зеркальных H и центральной V. Контуры всех версий
берутся из `scripts/brand.py`. На обложке знак объёмный, с периодическим бликом.
Отдельные статичные версии: `assets/hvh-mark-{dark,light}.svg`.

BCore и SoftDownloader располагают иллюстрацию справа; emberdeck и OpenCode
Pocket — слева. До 600 px ширины картинки включается мобильная композиция:
увеличенный текст и кнопка, приглушённая иллюстрация на заднем плане.

## Атлас и границы

`assets/profile-dark.svg` и `assets/profile-light.svg` содержат шесть `<view>`:

| Фрагмент | Содержание |
| :-- | :-- |
| `#hero` | Знак HVH, название и стек |
| `#bcore` | Воксельный мир |
| `#minecraft-panel` | Серверная панель emberdeck |
| `#softdownloader` | Каталог и установка пакетов |
| `#opencode-pocket` | Компьютер и телефон |
| `#signal` | Реальные contributions за последние 90 дней |

Каждый вид имеет размер **1200 × 420**. У корневого SVG нет `height`: высота
`<img>` определяется пропорциями выбранного вида. README использует `?v=hvh5`.
Тему выбирает `<picture>`, мобильную композицию — медиазапрос внутри SVG.

Каждая `scene-*` группа задаёт только перенос по вертикали. Внутри неё есть
локальный `clip-path="url(#scene-frame-имя)"` с рамкой 1198 × 418. Он обрезает фон,
иллюстрации, их влёт и частицы. Соседние сцены не должны менять пиксели выбранной
карточки. Порядок слоёв: фон и подсветка → содержимое → общий рельс и пакет.

## Появление

Позицию и движение нельзя задавать на одной SVG-группе: CSS `transform`
заменяет атрибут `transform`, а не дополняет его. Используется вложение:

```xml
<g class="art-anchor" transform="translate(965 201) scale(1)">
  <g class="art-enter">…иллюстрация…</g>
</g>
```

Внешняя группа хранит конечное положение. Внутренняя за **2.2 секунды**
прилетает сбоку и снизу с поворотом и изменением масштаба, слегка перелетает
конечную точку и фиксируется. `.from-left` меняет сторону влёта. Все пять
иллюстраций и все столбцы графика начинают появление одновременно через
.45 секунды. Порядок карточки не влияет на тайминг.

Тексты появляются с небольшим подъёмом, разделители прорисовываются, затем
проходит слабый световой свип. После появления текст и кнопки неподвижны.
`--idx` задаёт только роль элемента внутри карточки: шапка, название, описание,
подпись. Одинаковые роли появляются одновременно во всех карточках.

При сборке `scripts/svg_timeline.py` переводит используемое генератором
подмножество CSS keyframes в native SVG `<animate>`, `<animateTransform>` и
`<set>`. В опубликованных файлах нет CSS-анимаций с независимым стартом при
отрисовке `<img>`. Неизвестные конструкции останавливают сборку.

Интро проигрывается один раз от начала временной шкалы SVG. Прокрутка не
запускает отдельный таймер карточки. Для повторного просмотра интро нужна
новая загрузка SVG-ресурса.

## Движение после влёта

У иллюстраций есть внутренний 16-секундный цикл: блоки и деревья BCore,
загрузка сервера и график emberdeck, установка пакетов SoftDownloader,
QR-подключение и сообщения OpenCode Pocket. Все циклы, включая ауру, блик,
орбиту и пакет, используют один период 16s и одну фазу -10s из `motion.py`.
Пульсация и вентилятор имеют период 16/4s: их циклы также сходятся на общей
границе. Локальные события внутри иллюстраций остаются последовательными.
Фаза выбрана так, чтобы прилетал уже собранный объект. Иллюстративные графики
не являются телеметрией.

Пакет на рельсе `x = 26` — **одна** группа `.relay` на весь атлас. Его
горизонтальное положение задаёт родитель, SMIL меняет только вертикальную
координату. За 6.3 секунды он проходит от `-54` до `atlasHeight + 54`, затем
скрывается до следующего 16-секундного цикла. С общей фазой -10s первый полный
проход начинается через 6s. `atlas-clips` обрезает его по объединению рамок.
Рельс и его шесть индикаторов также находятся в одном слое `shared-rail`.
Все шесть `<img>` используют один ресурс с разными
фрагментами; они показывают разные участки одного пути.

При `prefers-reduced-motion: reduce` показываются статичные копии сцен без
SMIL-элементов. Анимированный слой, пакет, блик и временные эффекты скрыты.
Так настройка работает и для native SVG-анимации, которую CSS `animation:none`
не останавливает.

## Сборка и проверки

```sh
python scripts/design.py
python -m unittest discover -s scripts -p 'test_*.py' -v
```

Офлайн-сборка использует `assets/activity.json`. SVG редактируются только через
Python-исходники. Структурные тесты проверяют границы, разделение трансформаций,
один общий пакет, ссылки на SVG-ресурсы и корректную подстановку CSS-шаблонов.

Браузерная проверка требует `playwright`, `Pillow` и установленный Chromium:

```sh
python scripts/verify_visuals.py --output /path/to/review
```

Она проверяет геометрию, SMIL-эффекты, кадры появления, статичность reduced
motion, темы и размеры `<img>` из README. Сцены сравниваются с версией без
соседей в четырёх моментах времени; общий рельс и пакет проверяются отдельно.
Допуск сравнения сцен — 3/255 для сглаживания Chromium с отключённым LCD text.

Синхронизация проверяется одним кадром шести реальных `<img>`: при обычной и
поздней вставке, после прокрутки, на двух ширинах и в обеих темах. Перед снимком
все картинки выводятся в viewport: full-page screenshot сам по себе может
использовать старые offscreen-растры. Контрольные SMIL-маркеры выявляют сдвиг
часов; допускается небольшой межкадровый разброс растеризации. Дополнительно
сравнивается состояние всех эффектов через один и пять общих циклов.
PNG и JSON-отчёт сохраняются для визуального просмотра.

## Автообновление

GitHub Actions запускается на 17-й минуте каждого часа, при изменении README,
скриптов или workflow, а также вручную. Возможны задержки планировщика GitHub.
Генератор использует временный `GITHUB_TOKEN` и обновляет оба атласа, публичный
`activity.json` и таблицу между `PROJECTS:START` / `PROJECTS:END`.

Даты — UTC. Contributions включают публичные коммиты, issues, pull requests и
reviews. Нулевые дни остаются нулевыми. Все запросы и отрисовка завершаются до
записи файлов; ошибка API сохраняет предыдущий результат. При неизменных
данных новый коммит не создаётся.
